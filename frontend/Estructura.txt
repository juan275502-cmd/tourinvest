1. RESUMEN GENERAL
--------------------------------------------------------------------------------

El frontend de TourInvest es una aplicación SIN framework: HTML5 + CSS3 +
JavaScript vanilla (módulos ES), organizada en tres capas desacopladas por
contratos explícitos:

  · Capa de PRESENTACIÓN ..... páginas HTML + hojas CSS
  · Capa de LÓGICA ........... un driver JavaScript por página
  · Capa de DATOS ............ backend Java (Spring) en localhost:8080
                               o datos demo locales (localData.js)

El acople entre capas se hace SOLO a través de:
  · eventos del DOM .......... onsubmit / onclick
  · atributos data-* ......... data-vista, data-vista-panel, data-tab-id,
                               data-open-modal, data-close-modal
  · ids estables del DOM ..... getElementById(...)
  · endpoints HTTP ........... fetch() con Authorization: Bearer

No hay router ni store; no hay bundler configurado (el código usa la
convención de variables de entorno de Vite: import.meta.env.VITE_*).

5. FLUJO DE NAVEGACIÓN Y DE DATOS
--------------------------------------------------------------------------------

index.html ── "Acceder al Sistema" ──► view/login.html
                                           │
                    POST /auth/login       │
             { token, rol } ◄──────────────┘
                    │
                    │  sessionStorage: tourinvest_token · _nombre ·
                    │  _correo · _rol
                    │
                    │  redirección según RUTA_DASHBOARD[rol]
        ┌───────────┼────────────────┐
        ▼           ▼                ▼
  Administrador   Analista      Inversionista
  administrador   analista      inversionista
      .html         .html          .html
        └───────────┼────────────────┘
                    ▼
     driver dashboard*.js (valida el token)
                    │
                    │  llamarApi() + Bearer <token>
                    ▼
             API backend :8080 ── 401 ──► sessionStorage.clear()
                                          + redirect a login.html

Paso a paso:
  1. El usuario interactúa con la capa 1 (formularios onsubmit,
     enlaces laterales data-vista).
  2. El driver JS de esa página ejecuta la acción (capa 2).
  3. Según VITE_API_MODE, el driver usa localData.js (demo) o llama
     al backend con fetch + Bearer (real).
  4. El resultado muta el DOM (tablas, indicadores, toasts); el
     estado de sesión vive en sessionStorage (se limpia al cerrar
     la pestaña).
  5. Sin token → redirect a login.html; con 401 → logout.

7. CONTRATOS ENTRE CAPAS
--------------------------------------------------------------------------------

HTML ↔ JS (cableado declarativo)
  data-vista ................. enlace lateral del dashboard (destino)
  data-vista-panel ........... panel/vista de destino (mismo valor)
  data-tab-id / data-tab-target ... pestañas dentro de un contenedor
  data-open-modal / data-close-modal ... apertura y cierre de modales
  ids de DOM ................. todo getElementById del driver debe
                               existir en su HTML (lo validan los tests)
  name de los campos ......... el driver lee formulario.<name>.value

JS ↔ DATOS (HTTP)
  Cabecera ................... Authorization: Bearer <token>
  Content-Type ............... application/json
  401 ........................ logout automático (sessionStorage.clear)
  Errores de validación ...... { errores: { campo: mensaje } } →
                               .field--error + .field__mensaje-error
  Mensaje global ............. #mensaje-global
                               (.mensaje-global--error / --exito)
  Avisos no bloqueantes ...... TourInvestUI.toast(msg, success|error)

ESTADO DE SESIÓN (sessionStorage)
  tourinvest_token ........... token emitido por el backend
  tourinvest_nombre .......... primer nombre del usuario
  tourinvest_correo .......... correo del usuario
  tourinvest_rol ............. rol (Administrador|Analista|Inversionista)
