backend-servlets/
├── pom.xml
├── estructura-java.txt 
└── src/main/
    ├── java/com/tourinvest/backend/     ← Stack Spring Boot (API REST opcional en 8080)
    │   ├── TourinvestBackendApplication.java   ← clase main (Spring Boot) [corregido #A1/A2]
    │   ├── model/        ← entidades JPA (Usuario, Rol, Empresa, Accion, Portafolio, Inversion, Alerta, Notificacion, Reporte)
    │   ├── repository/   ← interfaces JpaRepository (una por entidad)
    │   ├── service/       ← lógica de negocio
    │   ├── controller/   ← endpoints REST (@RestController)
    │   ├── dto/           ← objetos de transferencia (login, registro, respuestas)
    │   ├── security/     ← JWT, filtros, config de roles + beans de config (CORS, PasswordEncoder, AuthenticationManager, SecurityFilterChain)
    │   └── exception/    ← manejo centralizado de errores (GlobalExceptionHandler)
    ├── java/com/tourinvest/domain/    ← Clean Architecture: Entities + Use Cases (demo)
    │   ├── domain/entities/      (Usuario, Empresa, PosicionPortafolio, Alerta, Reporte)
    │   ├── domain/repositories/  (UsuarioRepository, contrato)
    │   ├── domain/usecases/      (AutenticarUsuario, RegistrarUsuario, GestionarUsuarios, CrearAnalisis)
    │   ├── data/                 (InMemoryUsuarioRepository, impl en memoria)
    │   └── Main.java             ← demo ejecutable: `java -cp out com.tourinvest.Main`
    └── resources/
        └── application.properties   ← configuración Spring Boot (datasource MySQL, JPA, JWT, puerto 8080) [corregido #A1/A2]

NOTA: el paquete `config/` mencionado en esta guía no existe físicamente en el código;
      sus beans (CORS, PasswordEncoder, AuthenticationManager, SecurityFilterChain) viven
      en `security/SecurityConfig`. Además se mantiene la capa Clean Architecture
      `com/tourinvest/{domain,data}` + `Main.java`, que `estructura` no reflejaba.
